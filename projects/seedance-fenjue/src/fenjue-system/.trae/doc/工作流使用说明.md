# 焚决工作流使用说明

## 概述

焚决工作流是一个模块化的视频分镜生成系统。升级后，`.trae/scripts/run_workflow.ps1` 会真实调用大模型，按 4 个模块顺序生成需求分析、大纲规划、分镜脚本和资产详情，而不是只写提示词模板。

## 工作流结构

```text
用户输入
    ↓
模块1：需求分析
    ↓
模块2：大纲与节奏规划
    ↓
模块3：分镜脚本生成
    ↓
模块4：资产详情生成
    ↓
最终输出（合并 4 个模块结果）
```

## 目录结构

```text
.trae/
├── workflows/              # 工作流配置
│   ├── 焚决工作流.yaml
│   ├── 模块1-需求分析-配置.yaml
│   ├── 模块2-大纲规划-配置.yaml
│   ├── 模块3-分镜脚本-配置.yaml
│   └── 模块4-资产详情-配置.yaml
├── scripts/
│   └── run_workflow.ps1    # 实际执行入口
└── doc/
    └── 工作流使用说明.md
```

## 运行前配置

脚本支持两种模型来源：

### 方式一：OpenAI 兼容接口

适用于 OpenAI、DeepSeek、火山方舟、硅基流动、Moonshot 等兼容 `chat/completions` 的服务。

```powershell
$env:OPENAI_API_KEY = "你的密钥"
$env:OPENAI_MODEL = "gpt-4.1-mini"
```

如果是其他兼容平台，还可以额外设置：

```powershell
$env:OPENAI_BASE_URL = "https://api.deepseek.com/v1"
```

也可以不用环境变量，直接在命令里传：

```powershell
.\run_workflow.ps1 -ProjectName "项目名称" -UserInput "需求" -Provider "openai-compatible" -ApiKey "你的密钥" -BaseUrl "https://api.deepseek.com/v1" -Model "deepseek-chat"
```

### 方式二：本地 Ollama HTTP 服务

适用于已经启动本地 Ollama 服务的情况。

```powershell
$env:OLLAMA_MODEL = "qwen2.5:14b"
```

如果 Ollama 不在默认地址，可额外设置：

```powershell
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
```

运行时脚本会优先尝试连接 Ollama；如果不可用，再回退到 OpenAI 兼容接口。

## 使用方法

### 基本用法

```powershell
.\run_workflow.ps1 -ProjectName "项目名称" -UserInput "用户需求内容"
```

### 推荐用法

```powershell
.\run_workflow.ps1 -ProjectName "世纪银行大劫案" -UserInput @"
【需求描述】：一伙悍匪误闯海岛小银行，却撞上多国特工争夺封存军事绝密，引发爆笑动作冲突
【时长要求】：总共1分钟
【画面类型】：电影感写实风格
【画面比例】：16:9横屏
【其他要求】：节奏非常快，场面大，喜剧+动作
"@
```

## 参数说明

| 参数 | 必需 | 说明 |
|------|------|------|
| ProjectName | 是 | 项目名称，用于生成输出文件名 |
| UserInput | 是 | 用户的视频需求描述 |
| OutputDir | 否 | 输出目录，默认为 `.\output` |
| Provider | 否 | `auto` / `openai-compatible` / `ollama` |
| Model | 否 | 模型名；未传时优先读取环境变量 |
| ApiKey | 否 | OpenAI 兼容接口密钥 |
| BaseUrl | 否 | OpenAI 兼容接口地址，或显式指定 Ollama 地址 |
| OllamaBaseUrl | 否 | 本地 Ollama 地址，默认 `http://127.0.0.1:11434` |
| Temperature | 否 | 采样温度，默认 `0.7` |
| TimeoutSec | 否 | 单次请求超时秒数，默认 `600` |
| MaxRetries | 否 | 请求失败后的重试次数，默认 `2` |

## 输出文件

工作流执行后会在输出目录生成：

| 文件名 | 说明 |
|--------|------|
| `{项目名}_requirement_analysis.txt` | 模块1输出的结构化需求分析报告 |
| `{项目名}_outline_planning.txt` | 模块2输出的叙事结构和情绪节奏规划 |
| `{项目名}_storyboard_script.txt` | 模块3输出的完整分镜脚本 |
| `{项目名}_asset_details.txt` | 模块4输出的角色、场景、道具详情 |
| `{项目名}_final_output.md` | 合并后的完整结果 |

## 模块说明

### 模块1：需求分析

输入：用户原始需求  
输出：结构化分析报告

### 模块2：大纲与节奏规划

输入：模块1输出  
输出：分段大纲、情绪强度、功能与钩子规划

### 模块3：分镜脚本生成

输入：模块1 + 模块2 输出  
输出：可直接使用的分镜脚本

### 模块4：资产详情生成

输入：模块1 + 模块3 输出  
输出：角色、场景、道具的详细视觉描述

## 注意事项

1. 确保已安装 PowerShell 5.1 或更高版本。
2. 如系统禁止运行脚本，可执行：`Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`
3. 如果使用 OpenAI 兼容接口，必须至少配置密钥和模型名。
4. 如果使用 Ollama，必须先确保本地 HTTP 服务已启动且模型已拉取。
5. 工作流按顺序执行，后续模块依赖前序模块结果，任何一步失败都会停止。
6. 模型输出质量和稳定性取决于你选择的模型能力，建议优先使用中文表现较强的模型。
