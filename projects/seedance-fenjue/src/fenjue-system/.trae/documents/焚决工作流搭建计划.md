# 焚决工作流系统搭建计划

## 项目概述

搭建一个模块化工作流系统，运行环境为 **Agent Mode**（自动执行模式），实现以下流程：

```
用户输入
    ↓
模块1：需求分析（接收用户输入，输出分析报告）
    ↓
模块2：大纲与节奏规划（接收模块1输出，输出大纲）
    ↓
模块3：分镜脚本生成（同时接收模块1和模块2的输出）
    ↓
模块4：资产详情生成（同时接收模块1和模块3的输出）
    ↓
最终输出：根据用户指定的项目名称创建文件保存结果
```

## 工作流结构说明

| 连接关系 | 说明 |
|---------|------|
| 模块1 → 模块2 | 单向传递：模块1的输出作为模块2的输入 |
| 模块1+模块2 → 模块3 | 并行传递：模块1和模块2的输出**同时**作为模块3的输入 |
| 模块1+模块3 → 模块4 | 并行传递：模块1和模块3的输出**同时**作为模块4的输入 |
| 模块3+模块4 → 最终输出 | 合并输出：模块3和模块4的输出合并后，以用户指定的项目名创建文件保存 |

## 核心配置项

### 工作流配置需定义

1. **节点定义**：每个模块的名称、输入输出接口
2. **数据流向**：
   - Module1.Output → Module2.Input
   - Module1.Output + Module2.Output → Module3.Input
   - Module1.Output + Module3.Output → Module4.Input
   - Module3.Output + Module4.Output → FinalOutput
3. **文件保存规则**：根据用户输入的项目名称，合并生成最终结果文件

### 模块配置需定义

每个模块配置包含：
- 模块名称和描述
- 输入接口（接收哪些上游模块的输出）
- 输出接口（输出文件命名规则）
- 执行方式（在此工作流中是接收上游输出后执行）

## 工作流执行逻辑

1. 用户提供：需求输入 + 项目名称
2. 系统执行模块1，生成 `项目名称_需求分析.txt`
3. 系统将模块1输出作为模块2的输入，执行模块2，生成 `项目名称_大纲规划.txt`
4. 系统将模块1和模块2的输出**同时**作为模块3的输入，执行模块3，生成 `项目名称_分镜脚本.txt`
5. 系统将模块1和模块3的输出**同时**作为模块4的输入，执行模块4，生成 `项目名称_资产详情.txt`
6. 系统将模块3和模块4的输出合并，生成最终文件 `项目名称_最终成果.md`

## 执行方式

- **运行命令**：`.\run_workflow.ps1 -ProjectName "项目名称" -UserInput "用户需求内容"`
- **执行模式**：Agent Mode（自动执行，无需用户确认）
